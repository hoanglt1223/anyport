**Function discovery.** It starts from the framework's own analysis and adds, repeating until nothing new appears:

- exports and `module_start`/`module_stop`;
- runtime feedback addresses;
- jump-table targets;
- code addresses passed to the APIs that take one (`sceKernelCreateThread`, callbacks, alarms, vtimers, interrupt and thread-event handlers);
- `j` tail-call targets;
- code after a function's final jump or `eret`;
- for fixed-address (`ET_EXEC`) images, code pointers stored in data sections.

**CFG.** A block that ends in a branch includes its delay slot. Branch-likely edges are marked, a branch into another branch's delay slot gets a block of its own, and jump tables behind `sltiu` bounds are resolved.

**Runtime feedback.** The runtime appends `0x… missing_code` lines to a feedback file (`PSPRECOMP_FEEDBACK_FILE`, or `--feedback` on a runner). It records dispatch misses, entries into a unit at a PC it never translated, and jumps the interpreter takes to untranslated addresses. All of these now run in the interpreter instead of halting the guest.

`origin/main` was not rewritten. I did rewrite the unpushed commits once with `git filter-branch`, because Python's `write_text` had committed CRLF line endings. The only effect on pushed content is that `README.md`'s line endings were normalised.
